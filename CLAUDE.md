# Grading lab answers

The student is preparing for ENCOR 350-401 (v1.2). Grade answers by how they would
help or hurt on the exam, not by how closely they follow the lab.

## Files
- Student answers: `ANSWERS.md` in the lab folder. If it's missing or still blank,
  look for other notes in the lab folder and say which file you graded.
- Grading output: write every review to `GRADING.md` in the same lab folder. Put the
  newest review at the top under a heading `## Review — YYYY-MM-DD`. Never delete
  older reviews. Then give a short summary in chat.

## Feedback structure (in this order)
1. **Would cost exam marks**, worst first, each tagged with a risk level
2. **Gaps to study**: blueprint topics the answer is missing or the lab doesn't cover
3. **Already exam-ready**: what's right
4. **Lab adherence**: brief, last; skipped steps or missing output

## Risk levels (apply strictly)
- **High**: wrong fact or command. The student would pick a wrong option on a
  straightforward question (e.g. wrong stratum numbering, wrong escape sequence).
- **Medium**: right command, wrong idea of how or why it works. Likely to fail
  scenario or "which statement is true" questions.
- **Low**: right idea, imprecise or vague wording. Unlikely to cost marks;
  sharpen the wording.
Before assigning a level, write out (to yourself) the kind of exam question that
would catch the error. If you can't come up with a realistic one, it's Low.
If the config/command is correct and only the explanation is weak, it's at most
Medium, and say explicitly that the config part is fine.

## Accuracy
- Don't treat SOLUTION.md as automatically right. Check exam-relevant facts against
  standard Cisco behaviour. If unsure of a fact, say so instead of stating it.
- Separate lab-platform quirks (CML/IOL behaviour) from the textbook exam answer,
  and say which answer the exam expects.
- Tie each finding to a blueprint objective number (e.g. 3.3.a).

## Guesses
If an answer touches a topic the lab doesn't cover yet (e.g. VRFs in a Module 01
lab), say whether it's right or wrong and which module covers it. Don't count it
against the student.

## Answer file
Students fill in ANSWERS.md in the lab folder: per requirement "Commands used /
Command output / Explanation", per question "Answer". Keep any new answer files
that minimal.
