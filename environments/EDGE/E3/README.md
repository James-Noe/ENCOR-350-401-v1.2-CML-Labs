# EDGE E3 stage baseline (protected Internet edge + DC block)
Built and proven in CML by LAB-042. LAB-043/044 YAMLs = E3 plus their documented additions; LAB-042 proved the end state. Start point for LAB-043 (E3 with faults), LAB-044 (live evidence), LAB-045 (EDGE min E3) and MS-4.

**Configs.** E2 plus the DC block of H3, cold-boot tested (all 15 nodes BOOTED in 82 s; both BGP AFs per edge, OSPF, OSPF 99, tracks 10/20, HSRP 110 Active, AAA UP, ACLs on e0/0, PM-COPP on both control planes, FNF monitors on e0/0, e0/1, e0/2, `hostile.sh` on PROV-SRV1 all present). In the router configs the definitions (ACLs, class maps, policy map, flow record/exporter/monitor) are at the end and the interface and control-plane attachments follow them, because IOS drops an attachment whose definition is not loaded yet (the same reason the H3 AAA lines sit before `line vty`).

**Profile and topology:** E2 (8 licensed: HQ-EDGE1/2, PROV-ISP1/2, HQ-CORE1 stub, PROV-SRV1, HQ-SRV1, HQ-PC1) + IX and DMZ switches + DC lite + NMS1 (DC-RTR1, DC-SYSLOG1, DC-AAA1, DC-NMS1, DC-SW) = **15 running nodes** (unmanaged switches count). Runs alone. E2 cabling unchanged; PROV-ISP1/2 are identical to E2.

## Stage content (on top of E2)
- **Management standard on both edges** (H3 standard, VRF MGMT on e0/1.99): RADIUS group RADGRP (VRF MGMT, source e0/1.99, VTY list group then local, console `none`, enable `none`, accounting), `logging host 10.50.50.51 vrf MGMT` (trap informational, source e0/1.99), SNMPv3 `nmsuser` authPriv `NMSGROUP` access MGMT-HOSTS, NTP key 1 to 10.50.50.1 in VRF MGMT, VTY `access-class MGMT-HOSTS in vrf-also` and `ipv6 access-class NO-VTY6 in`. Accounts: `netadmin`/`netpass` (priv 15), `netops`/`opspass` (priv 1) on DC-AAA1; local `admin`/`Cisco123!` is the fallback.
- **EDGE-IN-V4 / EDGE-IN-V6 inbound on e0/0.** IPv4: bogon and Veridian-own-space sources denied with log (own space is `192.0.2.0/25` and `192.0.2.128/26`, not the /24: 192.0.2.192/26 is PROV-SRV1's block), eBGP from the peer address in both directions, probe echo-replies from the pinned target only (then `deny icmp any host <own> echo-reply log`), echo to the provider-facing address, `deny ip any host <own> log`, return traffic to the edge's pool and the DMZ block (TCP `established`, echo-reply, time-exceeded, unreachable), TCP 80 to 192.0.2.130, final `deny ip any any log`. IPv6: ND, ULA/multicast/own-/48 sources denied, eBGP from the peer, echo to the own address, return traffic to 2001:DB8:10::/48 (TCP established, echo-reply, time-exceeded, unreachable, packet-too-big), TCP 80 to 2001:DB8:10:60::150, final `deny ipv6 any any log`. EDGE1 peer/own 198.51.100.64/.65, probe 198.51.100.1, pool 192.0.2.0/26; EDGE2 203.0.113.64/.65, 203.0.113.1, 192.0.2.64/26.
- **PM-COPP on the control plane of both edges**, class order CM-ROUTING (eBGP + iBGP over loopbacks both AFs, OSPF, OSPFv3 `permit 89`, HSRPv1 UDP 1985 to 224.0.0.2, ND), CM-MONITOR (probe replies), CM-MGMT (SSH, SNMP, ICMP from 10.50.50.0/24 and 10.10.99.0/24; RADIUS and NTP replies from the DC), CM-UNDESIRABLE (Telnet, SSH from anywhere else, SNMP, TFTP, 514, 80, 443: dropped), CM-ICMP (v4 and v6 echo), class-default. Rates (lab-scaled): routing 64000 transmit/transmit, probe 8000 transmit/transmit, management 64000 bc 8000 transmit/drop, undesirable 8000 drop/drop, ICMP 8000 bc 1500 transmit/drop, default 16000 bc 4000 transmit/drop.
- **FNF on both edges:** FR-EDGE (IPv4 protocol, source/destination address, ports, input interface, bytes, packets, first/last timestamps), FE-NMS (`destination 10.50.50.60 vrf MGMT`, `source Ethernet0/1.99`, UDP 2055, template 60 s), FM-EDGE input on e0/0, e0/1, e0/2. IPv4 only (iol-xe fixed 15 s / 1800 s timeouts).
- **PROV-SRV1:** boot script adds 192.0.2.10/32 to eth0 and writes `/usr/local/bin/hostile.sh flood|probe|spoof|web|all` (target 198.51.100.65; flood = `ping -q -i 0.01 -s 1000 -w 40`).

## Measured behaviour (LAB-042)
(a) PASS exporter `destination ... vrf MGMT` with VRF source subinterface; tshark on DC-NMS1 decodes (`-d udp.port==2055,cflow`); no fallback. (b) PASS IPv6 ACLs match in CoPP classes (a `class-map match-any` with a v4 and a v6 `match access-group name` counts both). (c) PASS probe replies hit CM-MONITOR; without it they fall into CM-ICMP (043 F1). (d) PASS `ip nat inside` on e0/1 does not touch e0/1.99: MGMT traffic is never in the NAT table. (e) FNF input on e0/0 shows outside-global (pre-NAT) addresses for return traffic and records packets the ingress ACL drops (the monitor runs before the ACL); inside monitors (e0/1, e0/2) show inside addresses. (f) PASS: alpine `nc -z -w 2`, `ping -I 192.0.2.10` (root boot script adds the address), busybox `ping` has no `-f` and `-A` hangs the console; the flood runs as the console user. (g) PASS: `deny ip 192.0.2.0 0.0.0.255` blocks PC1 to PROV-SRV1 (192.0.2.200) in both directions of use (ping 0/3, web times out). (h) PASS HSRPv1 (UDP 1985 to 224.0.0.2) and OSPFv3 counted in CM-ROUTING (ACL counters rise 1 per 3 s and 1+ per s). (i) Normal control-plane rates per edge, 100 s window with 3 SSH logins, an SNMP walk and 60 pings at 1/s: routing about 3 kb/s, management 99 packets (14 kB, bursts per login), ICMP 0.8 kb/s at 1 ping/s, probe replies 1 packet / 5 s, class-default about 0.3 kb/s.

## Measured behaviour with the protection in place (UTC log timestamps, hosts ping 1/s)
- **Hostile flood during steady state** (`hostile.sh flood`, 40 s): 3809 sent, 39 answered, CM-ICMP exceeded +3770 packets; BGP, OSPF and HSRP uptime unchanged, track 10 Up, SLA failures unchanged, CM-MONITOR exceeded 0, SSH from DC-NMS1 during the flood works.
- **Silent failure EDGE1-ISP1** (`link stop`, 75 pings PC1 -> PROV-SRV1): track 10 Down +14-20 s (evidence applet log; LAB-043 re-measured 16.3-19.9 s), 18, 18, 20 lost pings (3-5 more than E2 unprotected: 14-15), HSRP Active -> Speak the same second; ISP-A eBGP stays Up while the outage is below the 180 s hold. `link start`: HSRP back to Active +32-48 s (seven runs: 34.4, 35.1, 37.6, 32.3, 42.8, 33.0, 48).
- **Cable pull ISP-A** (`shutdown` both ends): BGP both AFs down at once, track 10 Down +5-13 s (runs: 5.6-7.1, 8.3-11.9; LAB-043 11.1-12.6 s) after `%LINK-5-CHANGED`, 0 of 75 pings lost (3 runs); no ACL or CoPP drop of probe replies; recovery HSRP Active +35-48 s (runs: 35.5-42.6, 45.7-46.1) after the link comes up.
- **DC-AAA1 node stop:** RADIUS `State: DEAD`; local `admin` login works (about 11 s), `netadmin` is refused. **Stub-DC silent failure:** the edge loses its route to 10.50.50.60 after the OSPF 99 dead time (`% Subnet not in table`), the exporter's `Successfully sent` counter freezes while the cache keeps counting, exports resume 12 s after `link start`, the template is resent after 23 s; flows of the outage are lost.
- Restart rule: as E2/H3; NTP `sys.peer` on the edges after about 15 min.
